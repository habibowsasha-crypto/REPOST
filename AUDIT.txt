2. КОНЕЧНЫЙ ДИАЛОГ
======================================================================

Новые модули:

- laika_bot/ai_dialogues.py;
- laika_bot/ai_dialogues_repository.py;
- laika_bot/ai_dialogues_handlers.py.

План диалога:

- от 2 до 5 уникальных профилей;
- от 2 до 5 реплик;
- первая реплика отвечает на root post;
- в пилоте каждая следующая реплика отвечает на непосредственно предыдущую;
- профили циклически распределяются по конечному plan;
- один root post допускает один активный/сохранённый thread в этом пилоте;
- план сериализуется и валидируется до записи.

State machine:

- planned — готов к следующей генерации;
- generating — один запрос выполняется;
- review — одна следующая реплика ожидает решения администратора;
- completed — max_messages достигнут;
- cancelled — диалог отменён.

Перед каждой генерацией повторно проверяются:

- thread status и next_position;
- expires_at;
- root post существует, не удалён и имеет прежние revision/hash;
- current profile совпадает с планом и доступен;
- предыдущие позиции существуют, одобрены и не имеют разрывов;
- reply target существует и относится к тому же thread;
- отсутствует другой pending draft.

Каждая следующая реплика получает:

- root post;
- профиль канала;
- текущий account profile;
- ограниченные recent posts/knowledge chunks шага 11;
- все предыдущие одобренные реплики ветки;
- точный reply_to_ref;
- тему и конечную позицию thread.

Structured Output использует:

- prompt version: dialogue-reply-v1;
- schema version: dialogue-reply-schema-v1;
- validator version: dialogue-reply-validator-v1.

Результат всё ещё является только AICommentDraft. Accept создаёт локальную
approved AICommentMessage с role=draft и не создаёт Telegram job.

======================================================================
3. ДНЕВНОЙ ЛИМИТ И БОНУСНЫЕ МЕСТА
======================================================================

Базовый лимит:

- используется существующий profile.daily_limit;
- учитываются только AICommentMessage role=published с published_at внутри
  текущего локального календарного дня;
- draft/approved/rejected/external строки не расходуют базовый лимит;
- cooldown сохраняется и применяется после проверки quota.

Бонусный reply pool:

- новое versioned поле reply_bonus_slots хранится внутри style_json профиля;
- default = 3;
- допустимый диапазон = 0-20;
- значение редактируется в UI профиля вместе с лимитами;
- старые 8-строчные формы совместимы и получают default 3;
- 9-я строка формы задаёт явное значение.

Правила выдачи:

- grant возможен только после реального внешнего reply на role=published
  комментарий конкретного профиля;
- один bounded pool выдаётся не более одного раза на profile + local day;
- повторная доставка того же или другого reply в тот же день не наращивает
  quota бесконечно;
- idempotency key grant: profile + day_key.

Правила расхода:

- bonus slot разрешён только для reply-context;
- обычный новый комментарий bonus не использует;
- bonus начинает расходоваться только когда comments_today >= daily_limit;
- каждое использование равно одному slot;
- PostgreSQL сериализует конкурентные consumers через SELECT FOR UPDATE;
- repeated acknowledgement идемпотентен по profile/thread/source message;
- изменение reply_bonus_slots вниз ограничивает доступный pool текущим limit.

Reset:

- AI_COMMENTS_TIMEZONE=Europe/Moscow по умолчанию;
- timestamps в БД остаются UTC;
- query вычисляет UTC-границы локального календарного дня;
- day_key меняется ровно в 00:00 указанного timezone;
- отдельный reset worker не нужен;
- старые comments/grants/uses автоматически перестают участвовать в новом дне.

Важное ограничение:

Step 12 содержит repository hook record_ai_external_reply и quota ledger, но
production observer ещё не подключён, потому что публикация отсутствует. В Step
15 observer должен идентифицировать реальный Telegram reply, вызвать grant, а
publication transaction должна повторно проверить eligibility и атомарно
списать base/bonus quota непосредственно перед отправкой.

шаге 15. До Railway smoke версия остаётся кандидатом, а не релизом.
